# Codex 主控自动衔接

仅供主控读取，用户不需填写本文中的内部参数。先使用 `codexhost-delegation` 并读取当前 CLI help；以下是本机已确认的调用顺序，不替代当前命令的实际返回值。

## 1. 理解需求并准备内部依据

从当前项目和用户自然语言确定目标、有效授权及停止点；按需读取项目规则和状态。现有事实先查明，业务选择才问用户。包ID、计划版本/身份、依赖、技能、基线与证据位置由主控/调度者生成。
复用已有计划、状态与有效 DSH Lead；小任务可简写在现有文件里。计划字段与验收门按 artifacts.md，不能因简化交互而省略质量要求。

## 2. 交给唯一 DSH 调度会话

先定位实际可用的 `deepseek-harness`（必要时 harness list/inspect），模型/思考默认沿用 Harness 当前原生设置。已有 Lead 时核对项目、计划、会话角色和在途状态后用 `thread send`，不另建同一任务。
状态中没有绑定会话时，可用 `thread list --cwd <已核实项目根> --format compact` 查看少量候选；只读核对需要的候选，不读取无关项目历史。无法区分多个有效调度者时，只向用户提出可理解的选择，不让其提供内部ID。
若旧状态只记了 DSH 原生 session、Team target 或网页端口，先用当前会话列表及必要详情核对对应的 CodexHost Thread；这些原生标识不能直接充当 thread 参数。两个相似标题不证明两个会话都该继续，先核对真实执行者和在途任务，不能各发一次。

没有可复用 Lead、且创建在用户授权范围内时，执行：

```text
delegate start --harness deepseek-harness --cwd <项目根> --task-name <清晰的项目调度名称> --task <自包含的调度交接> --request-id <本次固定请求标识> --watch true --format compact
```

调度交接说明：加载 codexhost-workflow、角色 dispatcher、已核实项目根、原计划路径/版本身份及用户授权来源、目标/范围/验收条件、技能和验证权限、回退要求、状态/交付入口、停止点。由 DSH 再拆包和分配成员，不让用户复制这些字段。
要求 DSH 在原生 Team 中跟进成员，最后回报本阶段交付、自测、证据、风险和待决；不能只宣布“成员已启动”便当成工作完成。DSH 不替 Codex 给出最终验收。

读取返回值，确认实际 cwd、parent 和新 Thread 链接，并记录到状态。shell 退出0仅代表请求成功；超时或未知时先查原请求/会话，若确需重试使用相同 request-id，不能制造重复调度者。parent 有歧义时核对当前主控会话，不猜测其他父窗口。

## 3. 跟进交付，而不是让用户监工

优先使用 `delegate start --watch true` 或 `thread watch <Lead>`，检查返回的 watch 是否真的注册。已存在会话的 send/返工轮次也要按需注册新 watch；不是建立过一次就永久有效。
watch 是单次通知：watching 才表示已注册，alreadyTerminal 需立即 read；timedOut 不是任务失败，先 read 核对再按任务范围继续等待。宿主重启会丢失 watch，恢复后核对原会话并重新注册，不重新派发原任务。
完成通知只报告执行状态，不是验收。主控收到通知后执行 `thread read <Lead> --view result --format compact`，必要时增量读取 messages，再读取本地实际代码、产物与证据。
若 Lead 只回报正在执行、成员仍在跑，则继续原 Lead 的跟进/等待，不把它当作最终交付。不要持续无变化轮询、无意义唤醒 Codex 或为了保持运行重复发消息。
若 Lead 本轮已结束而成员仍在跑，向原 Lead 发送一次“核对成员/任务状态并继续跟进至本阶段交付”的后续指令，再确认新轮次和 watch；不重复原执行任务，也不在终止轮次循环 watch/read。持续同一阻塞且无新证据时如实报告。
watch 不支持或注册失败时，按当前 help 使用有界 wait/read 跟进，优先有变化再读。后台通知不可用不等于执行失败；若当前环境无法继续自动唤醒主控，明确告知交付仍待验收及恢复入口，不承诺无人值守完成。

## 4. Codex 验收与返工闭环

交付条件具备后，主控在当前合适的审查上下文或已授权的独立审查上下文中按原计划验收；不要求用户再发送“请验收包XX”。明确作者/审查身份、交付版与实际检查，不能把编写计划的人自动称为交付物作者。
需补正时用 `thread send` 把具体问题交回原 DSH 调度者，由其安排成员修复，继续跟进新修订。不要直接向执行成员另外派单；正常已授权补正不再次让用户批准整个阶段。
对用户只报告当前目标、实际进展、必要决策、最终验收结论及限制；技术字段保留在状态/证据中，非用户要排查时不要求其理解这些字段。

## 5. 额度、权限与实际边界

当前主控能执行工具且有可用额度时，这些衔接是工作流的一部分，不只是建议用户操作。若 Codex 无额度，原 DSH 继续批准范围内工作；其交付保持待验收，额度恢复后的主控先 read 和对账。
不能承诺通知能绕过额度恢复 Codex 推理。watch 依赖当前宿主，不能代替持久后台服务。CLI 不可用、会话未知、权限缺失或宿主断线时，保留事实并报告具体阻塞，不伪称“已派发/已监控/已验收”。
本技能的使用意图不扩大实际业务授权：只讨论/只读审查不启动执行；涉及新增真实费用、外部副作用或范围扩大仍按项目边界处理。只修改本工作流时，不借机开始用户提到但尚未指定具体任务的业务项目。
用户明确要求用本工作流执行，且项目允许该协作方式时，可使用其已经配置并获准的 DSH 模型资源完成调度和执行；这不授权新增收费服务、增额或项目业务侧真实模型/API、生产数据、发布等调用。项目若对现有 DSH 运行也有单独确认或预算要求，优先遵守；不因每次常规交接机械重复询问。
